## 1. Grounded Capability Baseline

CqrsLens is a **build-free static architecture analyzer and Model Context Protocol (MCP) server** tailored for .NET Clean Architecture and CQRS codebases:

- **Dual build-free scanners with parity**: A fast, parallel text scanner (`CSharpScanner` + `SourceMask` + `TextArchitectureScanner`) runs by default with no `dotnet build` or NuGet restore; an opt-in `--analysis roslyn` backend (`RoslynArchitectureScanner`) builds an in-memory compilation across source groups, evaluates `<Using>` directives from `.csproj` and ancestor `Directory.Build.props` / `Directory.Build.targets`, and injects minimal MediatR, FluentValidation, and EF Core contract shims when source declarations are absent.
  - Representative Release benchmarks reported in [README](../README.md#profiling-and-benchmarks): `SampleShop` in **10.4 ms** warm / **148 ms** cold (`text`) and **28.9 ms** warm / **805 ms** cold (`roslyn`); a **400-slice** synthetic 4-project solution in **319.3 ms** warm / **559 ms** cold (`text`); real-world 8-project / 295-file production API (`El-Hakim`) in **508 ms**.
  - Validated with zero text/Roslyn parity deltas against the 4-repository frozen benchmark suite (**105 projects, 154 requests, 154 handlers**) and the expanded 10-repository open-source legacy & enterprise gauntlet (**152 projects, 154 requests, 158 handlers, 191 validators, 24 DbContexts, 55 endpoints**; see [Hardcore Legacy Validation](hardcore-legacy-validation.md)).
- **Native CQRS + EF Core vertical slicing**: Automatically detects **MediatR**, **martinothamar/Mediator**, and **WolverineFx** conventions (plus custom `--markers` and `--handler-markers`), linking API entrypoints (MVC Controllers, Minimal APIs, FastEndpoints) → Request (with payload properties) → Validator (FluentValidation `AbstractValidator<T>` / `IValidator<T>`, FastEndpoints `Validator<T>`) → Pipeline Behaviors (`IPipelineBehavior<,>` in registered order) → Handler → `DbSet<T>` / `DbContext` + Domain Events/Notifications (`INotification` / `IDomainEvent`) → Notification Handlers.
- **DI-resolved persistence & service-call edges**: `ServiceResolutionIndexBuilder` resolves constructor-injected interfaces through concrete declarations and explicit MS-DI / Autofac registrations (failing closed on ambiguity), driving DI-resolved `HandlerToDbContextResolved` edges (`ResolvedEdges`) and method-body `ServiceCallEdges` (`From` → `Via` → `Method` → `To`).
- **Pre-implementation modeling & spec verification**:
  - `ArchitectureProposalEvaluator` (`--proposal` / `evaluate_architecture_proposal`) overlays proposed projects and reference additions/removals onto the scanned `.csproj` graph in memory.
  - `SliceDesignEvaluator` (`--slice-design` / `verify_slice_design`) validates versioned JSON slice specs against [cqrslens.slice-design.schema.json](../cqrslens.slice-design.schema.json) and enforces `--strict` CI exit code `4`.
  - `AgentSliceTestPlanGenerator` (`plan_slice_tests`) + the `model_feature` MCP prompt turn Given/When/Then acceptance criteria into boundary-mapped Red/Green/Refactor plans.
  - `AgentClaimVerifier` (`verify_claim`) evaluates structured `(subject, relation, object)` claims strictly against scanned facts and fails closed (`not determinable`) whenever ambiguity, incomplete scans, source filters, conditional MSBuild references, package-opaque wrappers, or unresolved dynamic dispatches prevent proof.
- **Wave 1 evolution modules** (core/analysis/reporting layer additions):
  - `ConditionalProjectReference` + `TargetFrameworks` parsing in `MsBuildProjectLoader` / `ProjectReferenceResolver`.
  - Extended `SliceDesign` fields (`properties`, `publishes`, `dispatches`, `persistence`, `dependencies`, `forbiddenDependencies`), `SliceDesignDrafter`, `ChangeImpactAnalyzer`, and `ArchitectureProposalEvaluator` coupling metrics ($C_a$, $C_e$, Instability $I$) + transitive layer checks + blast radius.
  - `TestProjectDiscovery`, `SafeXmlLoader`-backed `TrxTestResultsParser`, enriched `AgentSliceTestPlanGenerator`, and `TddCycleEvaluator` phase gating (`spec_draft` → `red` → `green_incomplete` → `verified` / `drifted` / `inconclusive`).
  - Expanded `verify_claim` vocabulary (`calls service`, `references project`, `touches entity`, `has test reference` and their absence forms).

### Positioning Summary & Honest Boundaries

- **Versus ArchUnitNET / NetArchTest**: Those tools excel at asserting arbitrary IL-level C# conventions inside `dotnet test` once a solution compiles (e.g., forbidding `System.DateTime.Now` or enforcing attribute placement on arbitrary internal classes). CqrsLens complements them by operating **before** compilation, understanding **CQRS vertical slices and EF Core/DI data lineage natively**, and serving **read-only architectural truth directly to AI coding agents via MCP**.
- **Versus NDepend**: NDepend provides deep commercial IL metrics (cyclomatic complexity, maintainability, trend baselines, NuGet/BCL dependency matrices) inside Visual Studio and CI. CqrsLens targets **zero-license, zero-build, CQRS-first automation** with PR Mermaid diffs, versioned slice design contracts, and fail-closed MCP verification.
- **Versus Structurizr / IcePanel**: Structurizr and IcePanel model multi-system C4 context, containers, deployment topology, and team ownership across polyglot architectures. CqrsLens operates inside a **.NET solution** to extract live code-verified architecture diagrams, request sequences, and ER diagrams without manual diagram drift.
- **Versus SonarQube**: SonarQube provides cross-language SAST, vulnerability detection, secrets scanning, and quality management. CqrsLens does not perform general security taint analysis or multi-language linting; it enforces **CQRS structural integrity, layer hygiene, and agentic design-to-implementation fidelity**.
- **Versus Generic LSP / Grep MCPs**: Grep and raw LSP servers force an LLM to expend tens of thousands of tokens reconstructing mediator pipelines, guessing DI registrations, and falsely concluding absence from missing text matches. CqrsLens compresses the entire solution into a compact architectural DNA summary, typed vertical slices, and **fail-closed `not determinable` verdicts**.

## 3. Security Audit Findings & Implemented Defenses

Because CqrsLens parses untrusted `.csproj` / `.trx` / `.json` / `.cs` files from arbitrary target repositories, runs a long-lived stdio MCP server (`cqrslens --mcp`), renders standalone HTML/SVG/Markdown artifacts, and executes inside GitHub Actions PR workflows, the codebase underwent a focused security review.

### Threat Surface & Defense Matrix

| Threat / Audit Finding | Risk & Attack Vector | Implemented Defense & Verification Surface | Residual Scope / Wave 2 Follow-up |
| :--- | :--- | :--- | :--- |
| **1. XXE, DTD & Billion Laughs XML DoS** | Untrusted `.csproj`, `Directory.Build.props`, `Directory.Build.targets`, or `.trx` files containing `<!DOCTYPE ...>` / `<!ENTITY ...>` external entities or recursive entity expansion parsed via unrestricted `XDocument.Load(...)`. | Created `SafeXmlLoader` ([SafeXmlLoader.cs](../src/CqrsLens.Core/Security/SafeXmlLoader.cs)) enforcing `DtdProcessing = DtdProcessing.Prohibit`, `XmlResolver = null`, `MaxCharactersInDocument = maxBytes` (default `10 MB`), and `MaxCharactersFromEntities = 1024`, reading files through `BoundedFileReader.ReadAllBytesStream`. Wired into `MsBuildProjectLoader`, `ProjectReferenceResolver`, and `TrxTestResultsParser`. | Audit any future XML loaders (e.g., `.sln`/`.props` extensions) to route exclusively through `SafeXmlLoader`. |
| **2. Unbounded File Read / Memory Exhaustion** | Oversized `.cqrslens.json`, `ARCHITECTURE.json` diff baselines, baseline stores, or symlinked special streams/FIFOs passed to `File.ReadAllText` exhausting process memory. | Created `BoundedFileReader` ([BoundedFileReader.cs](../src/CqrsLens.Core/Security/BoundedFileReader.cs)) with `DefaultMaxBytes = 32 MB`. Checks `FileInfo.Length`, `FileStream.Length` when seekable, and enforces chunked byte counting (`81,920`-byte buffer) during streaming reads, throwing `InvalidDataException`. Wired into `ConfigurationLoader`, `JsonReportDocumentReader`, `BaselineStore`, `SliceDesignCommand`, and `ArchitectureProposalCommand`. | Shared 32 MB streaming bound applies across CLI JSON/spec/proposal inputs and config/baseline stores. |
| **3. MCP Workspace Escape & Symlink Traversal** | MCP client or prompt-injected tool call passing `path: "../../etc"`, sibling-prefix paths (`/repo-evil` matching `/repo`), control characters, or in-workspace symlinks pointing outside the configured solution root. | Created `McpPathGuard` ([McpPathGuard.cs](../src/CqrsLens.Cli/Mcp/McpPathGuard.cs)) providing `TryValidateDirectory` and `TryValidatePath`: rejects null bytes (`\0`), ASCII control chars (`< 0x20`), and invalid path chars; normalizes relative paths against `workspaceRoot`; walks every ancestor path segment (up to `MaxSymlinkHops = 64`) resolving `Directory.ResolveLinkTarget` / `File.ResolveLinkTarget` to defeat directory-symlink escapes; checks segment-boundary containment via `Path.GetRelativePath` against canonicalized `workspaceRoot` and `allowedRoots` unless `--mcp-allow-external` is explicitly enabled. Wired into `McpToolInvoker` and `McpScanFingerprintCalculator`. | Keep path-containment assertions covered whenever adding new MCP file/directory arguments. |
| **4. MCP Stdio Framing & JSON-RPC DoS** | Unbounded `reader.ReadLine()` on malformed headers, header flooding (`>32` headers), out-of-order `Content-Type` before `Content-Length`, negative/duplicate/oversized `Content-Length`, unpaired UTF-16 surrogates skewing byte accounting, or duplicate JSON keys crashing `JsonObject.Create`. | Hardened `McpMessageFraming` ([McpMessageFraming.cs](../src/CqrsLens.Cli/Mcp/McpMessageFraming.cs)): enforces `MaxHeaderLineBytes = 8 KB`, `MaxHeaders = 32`, `MaxHeaderDrainLines = 256`, and `MaxContentLength = 32 MB`; handles case-insensitive headers in any order; rejects malformed/duplicate/missing/oversized `Content-Length` with explicit error `McpMessage` frames instead of silent breaks; drains oversized lines without buffering; peeks low surrogates in `ReadPayload` to avoid miscounting unpaired high surrogates. `McpRequestRouter` checks `HasDuplicateKeys` recursively on `JsonDocument` before materializing `JsonObject`. | Keep protocol framing bounds documented for large monorepo JSON responses. |
| **5. Unbounded MCP Scan Cache & Concurrency** | Repeated tool calls across distinct roots or modes growing `McpScanCache` indefinitely without thread safety or eviction. | Hardened `McpScanCache` ([McpScanCache.cs](../src/CqrsLens.Cli/Mcp/McpScanCache.cs)) with `lock (_gate)` synchronization and a bounded LRU eviction list (`MaxEntries = 8`), backed by `McpScanFingerprintCalculator` change detection. | Memory remains bounded to at most 8 cached `AnalysisResult` snapshots per server process. |
| **6. Regex ReDoS on Malicious C# Inputs** | Deeply nested brackets/whitespace in crafted `.cs` files triggering catastrophic backtracking in `RequestPropertyPopulator` (`(?:\s*\[\s*\]\s*)*`) or unbounded regex scans across deep-slice/DI/Wolverine analyzers. | Wave 1 security hardening removes the nested quantifier in `RequestPropertyPopulator` (`(?:\s*\[\s*\])*`) and applies `2000 ms` match timeouts (`RegexMatchTimeoutException` handled safely) across `[GeneratedRegex]` patterns in `RequestPropertyPopulator`, `ReceiverTypeMapBuilder`, `BehaviorRegistrationResolver`, `ServiceCallEdgeResolver`, and `WolverineHandlerDiscovery`. | Extend explicit timeouts to any remaining `[GeneratedRegex]` helpers (e.g., `DeepSlicePatterns`, `DispatchCallSiteScanner`) during periodic audits. |
| **7. HTML / SVG XSS & Untrusted Asset Loading** | Crafted C# identifiers, routes, or watermarks rendered unescaped into HTML/Markdown/Mermaid reports, or malicious scripts executed inside offline `--render svg` HTML reports. | `HtmlReportText.Encode` (`WebUtility.HtmlEncode`), `MarkdownEscaping`, and `MermaidDiagramText` escape user-controlled strings across all renderers. Browser `Mermaid` mode pins `mermaid@12.2.0` with a SHA-384 Subresource Integrity hash (`HtmlReportAssets.MermaidIntegrity`) and `crossorigin="anonymous"`. Zero-JS `--render svg` mode omits `<script>` tags and Wave 1 adds `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:;">`. | Maintain SRI hash updates strictly alongside Mermaid CDN version bumps. |
| **8. GitHub Action Path Traversal & PR Comment Duplication** | Untrusted `inputs.path` containing `..` escaping `$CQRSLENS_BASE_WORKTREE` when constructing `CQRSLENS_DIFF_BASE`, or unpaginated `gh api .../comments?per_page=100` missing the sticky `<!-- cqrslens-architecture-diff -->` comment on active PRs. | Wave 1 hardens [action.yml](../action.yml) to reject traversal segments in `CQRSLENS_PATH` before resolving the PR base worktree path, adds `--paginate` to the `gh api` comment lookup so sticky comments are reliably updated, and keeps optional `--slice-design` verification isolated from conflicting report output flags (`CliParser.Validate`). | Recommend pinning `AbdullahHakima/cqrslens` by commit SHA in security-sensitive workflows and restricting `pull-requests: write` / `security-events: write` to trusted trigger contexts (`pull_request`, not `pull_request_target` on untrusted forks). |
| **9. Prompt Injection & Untrusted Source Boundaries** | Adversarial instructions embedded in target `.cs` comments, string literals, XML docs, route attributes, or `.slice.json` scenarios attempting to hijack an MCP-connected LLM client or trigger destructive edits. | All **13** MCP tools are strictly read-only (`readOnlyHint = true` in `McpToolCatalog`); the server never executes target code, builds, or writes workspace files. `SourceMask` strips comments and strings before structural matching, `verify_claim` decides verdicts solely from deterministic scan facts (returning `not determinable` rather than LLM prose), and MCP prompts isolate user input in `role: "user"` prompt templates while `McpToolArguments` / `ModelJson.ValidateKeys` enforce strict schema typing. | Untrusted identifier/route/scenario strings still surface inside MCP tool outputs returned to the host LLM; MCP clients must treat returned source snippets and scenario strings as untrusted data and enforce human/workspace approval before file edits or `dotnet test`. |

## 4. Strategic Next Evolution Milestones

1. **Wave 2 CLI & MCP Wiring (Shipped & Validated)**:
   - Wired `McpPathGuard` (with explicit `--mcp-allow-external` opt-in) into `McpToolInvoker` and `BoundedFileReader` into `SliceDesignCommand` and `ArchitectureProposalCommand`.
   - Exposed `SliceDesignDrafter`, `ChangeImpactAnalyzer`, and `TddCycleEvaluator` through CLI flags (`--draft-slice`, `--impact`, `--tdd-check`) and **13** MCP tools + **3** workflow prompts (`model_feature`, `plan_refactor`, `review_architecture_change`), validated across 10 open-source legacy and enterprise codebases in [Hardcore Legacy Validation](hardcore-legacy-validation.md).
2. **Transitive Service & Repository Data Lineage**:
   - Extend `ServiceCallEdgeResolver` and `HandlerDbSetEffects` to bridge multi-hop service-to-repository-to-DbContext edges (while preserving fail-closed `not determinable` boundaries whenever any interface hop is ambiguous or external), enriching `verify_claim` (`uses DbContext`, `touches entity`, `calls service`) and `ChangeImpactAnalyzer`.
3. **Multi-TFM & Condition-Aware Project Graph Modeling**:
   - Build on `ProjectInfo.TargetFrameworks` and `ConditionalProjectReference` to support optional `--tfm` / MSBuild property profiles in `Analyzer` and `ArchitectureProposalEvaluator`, letting teams compare architecture checks and proposals under specific build configurations while continuing to fail closed when conditions are unset.
4. **Continuous Spec & TDD Drift Gates in CI**:
   - Combine `--slice-design` schema checks and `TddCycleEvaluator` `.trx` verification into a single PR gate artifact so teams can verify not only that architecture boundaries hold, but that every agreed `.slice.json` contract has corresponding passing tests in CI.
5. **Source-Generator & Messaging Ecosystem Extensions**:
   - Expand built-in convention detectors beyond MediatR, `martinothamar/Mediator`, and `WolverineFx` (e.g., MassTransit consumers/request clients and Rebus handlers) with the same text/Roslyn parity and diagnostic transparency.
